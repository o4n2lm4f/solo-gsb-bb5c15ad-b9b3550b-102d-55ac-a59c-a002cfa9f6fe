# 🎭 舞台排练口令同步系统（Cue Sync）

导演在浏览器里编排并发出排练口令，灯光、音响、布景等**目标岗位**在各自页面上确认。
系统实时汇总确认进度、标记超时与重复确认，并保证断线重连后状态不丢失、旧确认不串入下一条。

- **技术栈**：Node.js + Express（静态页面 / HTTP）+ `ws`（WebSocket）+ 原生 HTML/CSS/JS，无前端构建步骤
- **状态权威方**：服务端单场内存在内存中；任何客户端刷新、断网、重开标签页，重连后都以服务端快照为准

---

## ✨ 核心规则

| 需求 | 实现方式 |
| --- | --- |
| 导演创建含**序号、口令、目标岗位**的演出序列 | 导演控制端编排；序号按序列自动生成，待发口令可删除并重排序号 |
| 控制端发出**当前口令** | 一次只有一条 `active` 口令，全端实时高亮 |
| **仅对应岗位**页面可确认 | 服务端权威校验 `targets`，非目标岗位的确认被拒绝并写日志；前端同时禁用按钮 |
| **全部目标确认**才允许推进 | 未集齐时导演点推进被服务端硬拒绝；最后一个确认到达后口令自动关闭，导演再发下一条。确有需要时导演可**强制推进/关闭**，缺失岗位会写入日志 |
| **超时实时标记** | 每条口令可设确认时限；到时不关闭、不跳过，只标记未确认岗位为超时，进度条变红 |
| 超时后确认 | 仍然接受，但记为**迟到确认（late）**，不影响其他岗位 |
| **重复确认实时标记** | 已确认岗位再次点击：前端立即抖动拦截，服务端再次拒绝（`duplicate`）并写日志 |
| **不得串入下一条** | 每次确认必须携带当前 `cueId`；旧 id（刷新前缓存、延迟重发等）一律拒绝，不影响当前口令的确认集合 |
| **断线重连恢复** | 自动指数退避重连；重连后服务端立即下发完整快照：当前口令、谁已确认/谁未确认、超时/迟到标记 |
| **保留本场事件日志** | 发令、确认、拒绝、重复、超时、迟到、强制推进、上下线全部记录，服务端保留本场全部日志，支持导出 `.txt` |

## 🚀 快速开始

### 方式一：Node.js 直接运行（一条命令完成安装与启动）

```bash
npm run up
```

> `npm run up` = `npm install && node server.js`，首次运行也只需这一条命令。

随后浏览器访问**明确端口**（默认 `3000`）：

| 页面 | 地址 |
| --- | --- |
| 入口页 | <http://localhost:3000/> |
| 导演控制端 | <http://localhost:3000/director.html> |
| 岗位执行端 | <http://localhost:3000/position.html> |
| 指定岗位直达 | <http://localhost:3000/position.html?name=灯光> |
| 健康检查 | <http://localhost:3000/healthz> |

修改端口：

```bash
PORT=8080 npm start
```

### 方式二：Docker Compose（一条命令构建并启动）

```bash
docker compose up --build -d
```

访问 <http://localhost:3000/>。宿主机端口可改：

```bash
CUE_SYNC_PORT=8080 docker compose up --build -d
```

停止：

```bash
docker compose down
```

### 方式三：仅用 Docker

```bash
docker build -t cue-sync .
docker run --rm -p 3000:3000 --name cue-sync cue-sync
```

## 🎬 使用流程

1. 打开**导演控制端**，在「岗位」区创建岗位（如：灯光、音响、布景）。
   - 岗位页面可以**提前打开待命**：导演登记该岗位后，它会自动上线并计入在线名单（绿点）。
2. 在「编排口令」区填写口令内容、勾选目标岗位、设置确认时限（0 = 不计时），加入序列。
3. 各岗位用电脑/平板打开**岗位执行端**，选择或通过 URL 指定自己的岗位。
4. 导演点击 **发出下一条**：
   - 只有被选中的目标岗位页面上的「确认」按钮可点；其他岗位显示“非本岗位口令”。
   - 岗位逐一确认，导演端实时显示 `已确认 n/总数`、倒计时进度条。
   - 未在时限内确认的岗位被标红为**超时**；之后确认标记为**迟到**。
   - 全部确认后口令自动关闭，导演端出现绿色的「全部确认 ✔ 发出下一条」。
5. 遇到事故需要跳过：导演可**强制推进**（有下一条时）或**强制关闭本条**（最后一条时），缺失岗位进入事件日志。
6. 底部「本场事件日志」记录全过程，可随时**导出 .txt**；「开启新场次」清空序列与日志（岗位保留）。

## 🔌 WebSocket 协议摘要

连接：`ws://<host>:<port>/ws`，消息均为 JSON。

**客户端 → 服务端**

```jsonc
{ "type": "hello", "role": "director" }
{ "type": "hello", "role": "position", "name": "灯光" }
{ "type": "add_position", "name": "追光" }
{ "type": "remove_position", "name": "追光" }
{ "type": "add_cue", "cue": { "command": "黑场", "targets": ["灯光", "音响"], "timeoutMs": 30000 } }
{ "type": "delete_cue", "cueId": "cue_..." }
{ "type": "emit_cue" }                         // 正常推进；未全部确认会被拒绝
{ "type": "emit_cue", "reason": "force" }      // 强制推进
{ "type": "emit_cue", "reason": "force", "closeOnly": true } // 强制关闭最后一条
{ "type": "confirm", "cueId": "cue_..." }      // 必须携带当前口令 id
{ "type": "reset" }
```

**服务端 → 客户端**

- `hello_ok`：握手成功（`registered` 表示岗位是否已被导演登记）
- `snapshot`：**完整状态快照**（岗位、在线状态、全部口令及确认/超时/迟到状态、本场日志），握手后及每次状态变更时下发，**重连恢复只认它**
- `presence`：岗位在线数变化
- `confirmed`：某岗位确认的即时广播
- `cue_timeout`：口令到达时限
- `confirm_ack` / `confirm_rejected`：确认结果（拒绝原因包括非目标岗位、重复确认、旧口令 id）
- `toast` / `error`：操作被拒的提示

## ⚠️ 说明与限制

- 状态保存在**服务端进程内存**中（本场制）：重启进程会清空当前场次；这是排练工具的有意设计，
  「开启新场次」也会清空。需要持久化时可在此基础上接入 SQLite/Redis。
- 本系统面向可信的局域网排练环境，未做账号鉴权；任何打开导演端 URL 的人都能操作，
  请只在内网/本机使用。生产化时建议加访问口令或反向代理鉴权。
- WebSocket 路径固定为 `/ws`，经反向代理（Nginx 等）暴露时请记得开启 WebSocket 升级头。
